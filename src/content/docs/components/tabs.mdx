The `<Tabs>` component is used to group related, alternative pieces of content so users can select the context that applies to them. It is ideal for toggling between operating systems, package managers, or programming languages without forcing the reader to scroll past irrelevant instructions.

## How to Build Tabs

Organize multi-platform commands or alternative code implementations using tabs:

<Steps>
1. **Import Components:** Import both `Tabs` and `TabItem` from `@astrojs/starlight/components`.
2. **Define Tab Labels:** Pass a `label` attribute and optional file-icon to each `<TabItem>`.
3. **Nest Content:** Place code blocks or text directly inside the corresponding tab wrapper.
</Steps>

    **In Rich Text Mode:**
    1. Click the **+** (Add Block) button in the editor toolbar.
    2. Select **Starlight Tabs (2 Tabs)** from the dropdown menu.
    3. Fill in the **Tab 1 Label** (e.g., "macOS") and type its corresponding content.
    4. Fill in the **Tab 2 Label** (e.g., "Windows") and type its corresponding content.

    **In Raw Markdown Mode:**
    You can manually write out the `<Tabs>` and `<TabItem>` tags. This is necessary if you need *more* than two tabs, or if you want to add custom icons (like `icon="apple"`), as the visual CMS widget is optimized specifically for rapid, text-based dual tabs.

## Technical Writing Guidelines

When utilizing tabs in this knowledge base, adhere to the following stylistic rules:

* **Parallel Content Only:** Tabs should *only* be used for mutually exclusive alternatives (e.g., "If you are on Mac, read this; if on Windows, read this"). Never use tabs to break up sequential steps.
* **Keep Labels Short:** Tab labels should be concise (1-2 words). Avoid long phrases like "Instructions for Windows Users." Just write "Windows."
* **Don't Hide Core Concepts:** If an explanation applies to all users regardless of their OS or tool, put it *above* or *below* the `<Tabs>` block. Do not duplicate shared context inside every single tab.
* **Default to the Standard:** If there is a highly preferred or standard method (e.g., `npm` vs `yarn`), place it as the first tab so it renders open by default.
