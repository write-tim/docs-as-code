The `<FileTree>` component is used to display folder structures, file hierarchies, and project architectures. It transforms standard indented Markdown lists into visual, IDE-like directory trees, automatically adding the correct file and folder icons based on file extensions.

  <TabItem label="3. Sveltia CMS Authoring" icon="setting">
    *How writers add this component using the Sveltia CMS visual interface.*

    We configured a custom `filetree` widget in `public/admin/index.html` so writers can generate these diagrams simply by typing out lists.

    **In Rich Text Mode:**
    1. Click the **+** (Add Block) button in the editor toolbar.
    2. Select **Starlight File Tree** from the dropdown menu.
    3. Type your file structure into the widget using standard Markdown list syntax with hyphens (`-`). 
    4. Use the spacebar to indent sub-folders and files to create the nested hierarchy.

    **In Raw Markdown Mode:**
    Use the `<FileTree>` wrapper tag and write a standard indented markdown list inside it.

## Technical Writing Guidelines

When documenting project structures in this knowledge base, adhere to the following stylistic rules:

* **Highlight the Target:** If a procedure asks a user to edit a specific file within a larger tree, use **bold text** (`**filename.ext**`) to draw their eye directly to that file.
* **Prune the Tree:** Do not show the entire repository architecture unless absolutely necessary. Omit irrelevant folders (like `node_modules/`, `.git/`, or unrelated feature directories) to keep the diagram focused on the task at hand.
* **Use Inline Comments:** If a file's purpose isn't obvious from its name, add a brief explanation on the same line after a hash symbol (e.g., `# This controls routing`).
* **Always Include Extensions:** Starlight determines which icon to render based on the file extension. Always write out `.js`, `.json`, `.mdx`, etc., rather than just the file name.
