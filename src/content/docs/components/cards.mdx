Cards are structural layout elements used to highlight features, group related concepts, or guide users to subsequent articles. Starlight provides three interrelated components for this: `<Card>` (for static information), `<LinkCard>` (for navigation), and `<CardGrid>` (for layout alignment).

  <TabItem label="3. Sveltia CMS Authoring" icon="setting">
    *How writers add this component using the Sveltia CMS interface.*

    Unlike Asides or Steps, which are frequent mid-article elements, Cards are structural layout tools. Because we configured `astro-auto-import` in `astro.config.mjs`, authors can type these directly into the raw editor without needing complex CMS widgets or `import` statements.

    **In Raw Markdown Mode:**
    1. Type `<CardGrid>` to open the layout block.
    2. Add your individual `<Card>` or `<LinkCard>` tags inside the grid.
    3. Ensure you close the block with `</CardGrid>`.
    
    > **Pro Tip:** For `<LinkCard>`, you can link to relative internal pages (e.g., `href="/components/steps/"`) or external URLs (e.g., `href="https://github.com"`).

## Technical Writing Guidelines

When utilizing cards in this knowledge base, adhere to the following stylistic rules:

* **Use the Right Card:** 
  * Use `<Card>` if the content is purely informational and the user isn't expected to click it.
  * Use `<LinkCard>` if the entire purpose of the card is to route the user to another page.
* **Keep Descriptions Brief:** The `description` prop on a `<LinkCard>` or the body text of a `<Card>` should be a maximum of two concise sentences. 
* **End of Article Routing:** `<LinkCard>` is highly recommended at the very bottom of procedural articles (under a "Next Steps" or "Related Guides" heading) to keep readers moving through the documentation.
* **Pair with Grids:** Always wrap adjacent cards in a `<CardGrid>`. Without the grid wrapper, cards will stack at 100% width on large screens, which disrupts reading flow.
